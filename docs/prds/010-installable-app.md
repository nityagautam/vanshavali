# PRD 010 — Installable app (add to home screen)

- **Status:** Implemented (2026-10-27)
- **Owner:** Ashutosh Mishra

## Problem
Family members should be able to keep the Vanshavali on their phone like an app — one tap from the home screen, full-screen, and usable with a poor or no connection.

## Solution
- **Web app manifest** (`public/manifest.webmanifest`): name "वंशावली — Gautam Vanshavali", short name "वंशावली", `display: standalone`, Parchment paper colours, 192/512 icons plus a maskable 512.
- **Icons** (`public/icons/`): the "व" brand mark on Parchment ink with an accent dot, generated by `scripts/generate-icons.mjs` (headless Chrome, real display font). Includes `apple-touch-icon` and a 32 px favicon; `favicon.svg` updated to the same mark.
- **iOS tags** in `index.html`: `apple-mobile-web-app-capable`, title, status-bar style, `apple-touch-icon`. `theme-color` follows the light/dark theme (inline script + App effect).
- **Service worker** (`public/sw.js`, registered in production only): pages network-first with the cached shell as offline fallback; hashed `/assets/*` cache-first; photos, avatars and fonts stale-while-revalidate (capped at 150). **`/api/*` is never intercepted** — family data is live, and the app already falls back to its bundled snapshot offline.
- **"Install app"** entry in the More menu (phone sheet and desktop ⋯ menu), open to everyone: triggers the browser's install prompt where available (Chrome/Edge/Android, captured from `beforeinstallprompt` in `src/utils/install.js`); on iOS it opens "Add to Home Screen" instructions (Share → Add to Home Screen). Hidden once the app is installed/running standalone.
- **Headers** (`vercel.json`): `/sw.js` never cached and `Service-Worker-Allowed: /`; manifest 1 day; icons 1 week.

## Verified (headless Chrome)
Manifest parses with no errors; Chrome's installability check returns no errors; service worker activates and caches the shell and media; a reload with the network offline renders the app with all 344 cards; the install prompt fires once on tap; the iOS instructions sheet opens; the entry is hidden when already installed.
Not verified on a real device: the actual install flow on Android Chrome and iOS Safari.

## Notes / follow-ups
- Bump `VERSION` in `sw.js` to force every client to drop its caches.
- The service worker only serves cached pages when the network fails, so a new deploy is picked up on the next online visit.
- Possible later: a one-time dismissible "Install" banner on mobile; push notifications are out of scope.
